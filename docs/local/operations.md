# 使用与维护

Tokenory 是 macOS 15+ 的本地菜单栏应用。Apple Silicon 下载版使用 Shenzhen Hiko Technology Co., Ltd. 的 Developer ID 签名，并附有 Apple 公证票据。从 ZIP 解压后，将 App 拖入「应用程序」即可使用。[下载最新版本](https://github.com/ryekee/tokenory/releases/latest)

## 日常使用

打开 App 后，从菜单栏进入今日面板，选择「查看统计」打开单实例窗口。统计窗口支持今日、7 天、30 天、全部、自定义范围及工具、提供方、模型、来源筛选。`⌘O` 打开统计，`⌘,` 打开设置。维护时可用 `open <Tokenory.app> --args --show-dashboard` 显式展示窗口。

收起面板或关闭所有窗口后，采集继续。默认每次扫描结束后 60 秒再次扫描，不重叠运行。退出 App 后引擎停止；重新打开补扫仍存在的日志。断管/父应用结束后引擎退出，不另装 LaunchAgent。

「登录时启动」默认关闭，采用系统 `SMAppService.mainApp`，并显示真实状态。若系统要求允许，按设置中的入口前往系统登录项设置。未实际重新登录前，不把已注册视为启动验收。

设置「通用」可选择跟随系统、English 或简体中文，切换即时生效。金额统一为美元。价格页只读，不需要录入费率。点击供应商标题可独立展开或收起；搜索时自动展开匹配供应商。

## 数据与来源

- 数据：`~/Library/Application Support/Tokenory/tokenory.sqlite3`
- Tokenory 独立核心缓存：同目录 `core/`
- 设置：同目录 `settings.json`
- 自动操作前备份：同目录 `backups/`
- 本次原始历史导出：同目录 `imports/`

保留 usage、模型、日期、身份、来源与计价元数据；不把提示词正文写入账本。源日志只读。现有 tokens CLI 的登录、缓存、提交路径不被接管。42 个客户端入口的自动发现、缓存要求和统计粒度见 [来源说明](sources.md)。设置「采集」可以按工具编辑额外目录。

历史导入先预览再提交。原时区未知时要显式保留原始日期；快照末日未结束时另行确认部分覆盖。相同日期/工具只选择一个有效来源；原始行继续保存。相同文件重复导入不增加用量。修改已有选择时，撤销对应批次后重新预览导入；存在后续依赖时先撤销后续批次。

每个工具用它在文件中的日期范围确定覆盖，其他工具更早的日期不会把该工具的历史范围扩大。替换范围内移除的日/模型行退出有效统计；重叠的其他来源须明确选择。预览后受影响范围有新记录时，重新预览。

## 价格

价格更新会自动补齐待计价记录，回填前自动备份。已有金额保持原快照。重估已有记录会展示原小计、新小计、仍待计价 tokens；提交前备份，提交时复查记录是否改变。来源原成本保留。

源成本为零不意味着免费；缺模型、费率或速度档位信息时显示待计价。日汇总以基础参考价估算，不能复原单请求长上下文和历史折扣。DeepSeek 按官方峰谷时段、周末和节假日计价，见 [价格说明](pricing.md)。

## 备份与恢复

在设置「数据」中选择新文件名创建一致性 SQLite 备份。备份包含用量、导入批次、有效覆盖、价格快照；路径设置和系统登录项不随数据库备份迁移。

恢复时先停止 worker，检查备份完整性与版本，备份当前库，再通过 SQLite backup API 进行替换，随后重启 worker。损坏或新版本备份不替换当前库。恢复不删除源日志。

CLI 维护入口在 App bundle 的 `Contents/Helpers/tokenory`；直接运行 `restore` 或其他写命令前退出 App。`report` 和一致性 `backup` 可以在 App 运行时使用。导出 JSON 保留来源和计价依据；CSV 用于人工核对。已有目标文件不会被静默覆盖。

```sh
<helper> --data-dir <独立目录> report --group-by client --json
<helper> --data-dir <独立目录> backup /absolute/new-backup.sqlite3
<helper> --data-dir <独立目录> restore /absolute/backup.sqlite3
```

## 停用与卸载

先关闭设置中的登录启动，然后退出 Tokenory，删除 App 即可。数据目录默认保留，便于重新安装或手动归档。不会修改现有 tokens、Claude Code、Codex 安装或日志。

## 尚需长期观察

自然日持续运行、真实睡眠唤醒、用户开启登录项后的重新登录，必须分别观察。单元测试中的模拟日界只证明日期查询刷新逻辑，不等于这些系统行为已经验收。

数据库 schema 3 会在升级前备份，将旧的 provider 参与事件键迁移为工具 + 稳定响应身份，并合并既有重复。旧备份恢复时执行相同迁移。提供方仍作为可更新属性保留。

## 总览与活动历史

总览显示所选日期的 Tokens、估算费用、活跃天数和使用模型数。上方趋势同时展示 Tokens 柱状和费用折线；工具和模型排行通过共用分段控件切换用量或费用。

活动日历和用量走势独立显示最近 12 个月，工具、提供方和模型筛选仍生效。日历固定使用 YlGnBu；悬停日期直接显示摘要，点击日期查看当日，用“返回此前范围”恢复日期。走势支持每日/30 天移动平均和工具筛选，日期按时间正序排列；右上角始终是原始总量。

活动查询直接聚合有效账本，不受明细分页影响，不重复计算被覆盖的导入来源。零用量日期不计入活跃天数。零 Token 且无费用的合成记录按零处理；未知费用保留为空并仅中断对应模型的走势区间，不显示为零费用；部分已计价总额标为已知估算。详细依据使用悬停或当日摘要查看。

总览默认近 7 天。编码习惯是独立面板，采用最近 12 个月的数据，显示最高产的一天及其用量占比、单日最高、周日到周六的分布和 0–23 时分布。小时分布按北京时间和真实事件时间戳汇总；按日导入及时间戳与账本日期不符的数据保留在未分配量中。

日历展示数据在报告更新时构建，hover 仅更新提示卡片。走势按指标、平均模式和工具缓存，报告刷新后失效。总览使用懒加载，返回页面时复用展示数据。

编码习惯的星期和小时图在宽窗口并排，窄窗口上下排列。明细和来源页首次访问后保留滚动与展开状态；来源页只请求来源数据，扫描结束后更新，不再为了展示来源而加载价格目录。
