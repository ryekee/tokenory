# Native Overview Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement task-by-task.

**Goal:** Ship the approved overview prototype against real effective ledger data.
**Architecture:** Rust aggregates daily client/model history in a separate read-only activity response. Swift constructs calendar and moving-average display data, renders native controls and charts, and keeps the selected-range report independent of annual history.
**Tech Stack:** Swift 6, SwiftUI, Swift Charts, Rust, SQLite.
**Spec:** Approved overview-v2.html in .superpowers/brainstorm/76980-1794566090/content; user approval in this chat.

## Global Constraints
- Preserve current uncommitted changes and all pricing/source-selection rules.
- Fixed YlGnBu calendar, no palette preference. Recent 12 months for calendar and model history; dimensions follow global filters, date selection only changes the upper report.
- Native labels only; explanations in help/popovers, conditional missing-price information. English and Chinese.
- Unknown costs never become zero; moving averages never change raw totals.
- No release/version change, no automatic commit of unrelated work.

## Review Focus
- Source overlap, pagination and dimensions must not alter aggregation correctness.
- Zero-usage days are inactive; missing costs remain distinguishable from free usage.
- Calendar dates use Beijing reporting time; partial current day remains inspectable.
- Rolling average includes zero-usage calendar days and preserves unknown intervals.
- Rapid filtering must not publish mixed report generations.
