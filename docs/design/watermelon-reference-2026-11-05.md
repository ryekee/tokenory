# Tokenory：Watermelon UI 组件参考

日期：2026-11-05。状态：参考方案已实现；实现和验证记录见末节。

## 推荐方向

采用「紧凑的原生数据工作台」：保留 macOS 窗口、系统字体和交互；内容区用实色背景、轻微表面色差和统一间距建立层级。蓝色用于主要数据与选择态，其他颜色仅在区分类别或状态时出现。保留现有 menubar Liquid Glass 面板。

Watermelon 提供 React / Tailwind 组件。这里借鉴布局、信息层级和交互，不向原生 App 引入 React、WebView 或整套 Web 依赖。

## 改造前的问题（调研记录）

- 主页面：日期和三个筛选器分占两行，摘要与图表之间留白较多。在本次观察的默认窗口里，首屏只能看到工具／模型分区的标题，分布数据在下方。
- 摘要：Token 和费用总额已可读，但缺少与趋势、分布之间的整体编排；待计价提示与它对应的费用指标相隔较远。
- 图表：已有真实日期轴与稀疏刻度，不需要推倒重做。现在缺少鼠标指向某一天时的精确读数；工具和模型则仍是纯文字列表。
- 设置：“通用”用 grouped Form，“价格”“采集”“数据”用不同的纵向堆叠方式。固定高度对通用页留下大量空白，采集页却像原始配置表单。

上述判断来自运行中的 App、`DashboardView.swift`、`UsageViews.swift` 和 `SettingsView.swift`。

## 建议的页面编排

主页面由上至下：

1. 标题与日期范围同排；工具、提供方、模型筛选紧凑排列，窄窗口允许换行。
2. Tokens 与已知费用估算相邻；待计价量放在费用下方。
3. 主趋势图，右上角切换 Tokens／费用；鼠标指向某一天时显示日期和完整数值。保留零基线、真实日期和少量刻度。
4. 工具占比与模型排行并列。减少主图外的垂直留白，让分布数据更早进入视野；窄窗口改为上下排列。

设置使用左侧分类、右侧内容。通用页是紧凑设置行；采集页按“扫描”“额外目录”分组；价格页把状态与操作放在顶部、费率表折叠在下方；数据页对齐目录、备份和恢复操作。通过统一对齐和分组解释页面，不额外增加介绍性副标题。

建议视觉尺度作为后续原型起点：主要面板圆角 12 pt、内容内边距 16–20 pt、面板间距 12–16 pt；字号与行高仍遵循 macOS 系统排版。使用表面色差与很浅的阴影，避免厚描边和多层套卡。浅色与深色都需验证。

## 数据与实现约束

- `UsageReport` 已有 `daily`、`clients`、`providers` 和 `models`，足够支持每日趋势、期间占比和排行。按“日期 × 工具”堆叠需要另一个聚合维度，本轮视觉改造不默认扩展它。
- 不把 `recordCount` 标成“请求数”。模型单次请求和导入汇总行的粒度不同，`requests` 本身也是可空字段。
- 不照抄收益类示例里的绿色上涨提示。用量增加不等于表现更好；上一周期比较需要真实对照数据，不能用示例百分比占位。
- 缺失费用继续显示待计价／不可用；部分计价必须继续可见。不要把它画成零费用。
- `SummaryView` 同时被主页面和 menubar 使用。后续调整应限制在主页面呈现，保留 `compact: true` 的现有布局。
- 设置分组、筛选排版、主图读数和排行展示可以集中在原生视图层完成；不需要修改采集、导入和价格计算逻辑。

## 原生实现与验证

- 主页面：摘要与每日图合并为主分析区，工具用量使用环图与直接标注，模型用量使用按 Tokens 排序的横条。分布区域在较窄内容区上下排列。
- 筛选：日期移入工具栏弹出层；自定义范围经“应用”提交。模型支持搜索，明细页来源筛选可换行。
- 图表：保留真实日期轴和零基线；实现指针／点击读数。短周期限制柱宽，日期标签与每日柱对齐；没有价格的数据不绘制成零费用。
- 设置：四个分类共用左侧导航与分组容器，窗口高度按内容类别调整，字段标签与控件对齐。
- 明细：数值右对齐、交替行底色、显示当前记录范围和总数。保留原有记录详情与分页逻辑。
- menubar 的 `MenuBarView`、紧凑 `SummaryView` 与 Liquid Glass 保持原实现。采集、导入、数据模型和价格计算未改动。
- 构建修正：关闭 Xcode 的独立 Debug dylib，解决当前 ad-hoc hardened 签名组合下的启动失败；保留运行时签名校验。

验证结果：

- Release 构建与 `codesign --verify --deep --strict` 通过，更新本机 `~/Applications/Tokenory.app`。
- 项目 macOS XCTest：6 项通过，0 失败，覆盖引擎生命周期、UsageStore 与双语文案；没有把这些测试描述为 UI 自动化覆盖。
- 实窗检查了中文深色和英文深色／浅色主页面与设置布局；模型搜索、未计价状态、日期预设与自定义应用、全部历史分布、图表点击读数、明细分页均完成检查。
- 浅色检查使用临时 App 外观覆盖；覆盖已从源码移除，交付版本跟随系统。语言检查使用进程参数，未更改持久语言偏好。
- `git diff --check` 通过，167 个文案键均有英文和简体中文。

连续鼠标悬停、VoiceOver 完整流程和最小窗口尺寸未做独立人工验收；本轮没有执行备份恢复、重计价或系统登录等非视觉操作。
